# Plan: Abella Web

**Version:** v11 (draft, 2026-10-23)

**Status:** draft, pending production deployment. Do not publish this
version or point `plans/abella-web/README.md` at it until the production
OAuth app, Worker, DNS, and site deployment succeed. v10 remains the
source of truth until then.

This draft records the GitHub OAuth sidequest and the changed
authentication decision. It is a delta note, not a full replacement for
the v10 text. When publishing v11, fold this note into a copy of v10 and
publish the resulting full document.

## Scope

The change is limited to how a GitHub token is obtained. The GitHub
workspace, Octokit client, public and private read path, atomic Git Data
API commit path, conflict handling, and workspace file policy are
unchanged.

## Changed decision

v10 chose personal access tokens only and avoided a redirect OAuth flow
because the site was purely static. v11 accepts one small Cloudflare
Worker as the token-exchange component, so the site can offer
`Sign in with GitHub` without exposing the OAuth client secret.

The flow is a popup, not a full-page redirect, so the prover, editor,
unsaved edits, and pending commit stay alive:

1. The main tab generates `state` and a PKCE S256 verifier/challenge.
2. It opens a popup on GitHub's authorization page.
3. GitHub redirects the popup to the static
   `web/github-callback.html` page.
4. The callback page posts `code` and `state` to the opener and removes
   the authorization code from its URL.
5. The main tab verifies the origin, source, and state, then sends the
   code and verifier to the Worker.
6. The Worker exchanges the code with GitHub using the client secret and
   returns only `token` and `scope`.
7. The main tab validates the token with `GET /user`, stores it in
   `sessionStorage`, and hands it to the existing GitHub workspace path.

## Security decisions

- The OAuth client secret exists only as a Cloudflare Worker secret.
- PKCE S256 is required; the verifier stays in the main tab.
- The Worker allows only the exact site origin, uses a fixed redirect
  URI, caps bodies at 4 KiB, times out after 10 seconds, does not follow
  redirects, and logs no codes, verifiers, tokens, or secrets.
- The token and its scope/account metadata stay in `sessionStorage`.
  They never enter `localStorage`, a URL, the DOM, logs, or error text.
- `public_repo` is the default. `repo` is an explicit, account-wide
  opt-in; a fine-grained PAT remains the least-privilege path.
- A later 401 clears the token and prompts for reconnection. A 403 does
  not clear it.
- The Worker `/github/config` route is the availability flag: when it is
  missing or rejects the origin, the site hides OAuth and keeps the PAT
  path.

## Implementation status

- Phases 0 through 3 are complete: development OAuth app, Worker with
  tests and CI, static callback page, frontend OAuth client, dialog
  integration, saved-token loading, reconnect, account display, and 401
  handling.
- A real-account connect and commit round trip succeeded against the
  development app. The resulting test commit was removed from the
  `try-merge` branch of `chaudhuri/abella`.
- Verification passed: `npm run check`, `npm run web:test` (76 tests),
  `npm run web:size`, `make web` with the wasm backend,
  `make oauth-worker-check` (27 Worker tests), a headless Chromium smoke
  test that loaded an example and processed 60 commands, and a public
  GitHub read without a token.
- The local production build correctly falls back to PAT-only when the
  production Worker hostname is not deployed.
