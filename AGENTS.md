## Code Style & Comments
- **Write self-documenting code:** Use clear variable and function names instead of adding inline comments.
- **No obvious comments:** Do not add comments that merely repeat what the code does.
- **Comment only the "Why":** Only use comments to explain complex logic, edge cases, business rules, or non-obvious workarounds.

## Commit Messages
- **Be concise:** Keep commit messages brief, punchy, and strictly under 72 characters for the subject line.
- **Format:** Use the Conventional Commits format (e.g., `feat: add auth handling`, `fix: resolve null pointer`).
- **No fluff:** Do not include long explanations, conversational language, or summaries of every single line changed.
- **Focus on intent:** Briefly state *what* changed and *why*, not *how* (the diff already shows how).
